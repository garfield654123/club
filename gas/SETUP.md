# 部署步驟（GAS Web App + Google Sheets 後端）

## 1. 建立試算表與 Apps Script 專案
1. 到 Google Drive 建立一個新的 Google 試算表，例如命名為「115學年度社團志願選填」。
2. 開啟該試算表 →「擴充功能」→「Apps Script」，會開啟一個綁定此試算表的 Apps Script 專案。
3. 把預設的 `Code.gs` 內容清空，貼上本資料夾的 `Code.gs`。
4. 在專案裡新增檔案 `Setup.gs`，貼上本資料夾的 `Setup.gs`。
5. 再新增一個檔案 `Seed.gs`，貼上本資料夾的 `Seed.gs`（國中部、高中部的完整名冊/社團/公告都整理在這一份檔案裡，不再拆成好幾個 Seed 檔）。

## 2. 建立分頁結構
1. 在 Apps Script 編輯器上方的函式下拉選單選擇 `initSheets`，按執行（▶）。
2. 第一次執行會跳出授權畫面，選你的 Google 帳號 →「進階」→「前往（專案名稱）」→ 允許。
3. 執行完成後回到試算表，應該會看到 `Students / Clubs / Config / Notices / Responses` 五個分頁，且都已經有標題列。

## 3. 匯入國中部／高中部資料（現成資料，一鍵匯入）
1. 函式下拉選單改選 `seedJunior`，執行——會寫入國中部 596 筆學生名冊（七、八、九年級，體育班已排除）、18 筆社團備份、`Config`/`Notices` 各一列 `junior` 的資料。
2. 函式下拉選單改選 `seedSenior`，執行——會寫入高中部 182 筆學生名冊（101/102/103/201/202/203/301/302/303 共 9 班，體育班已排除）。⚠️ `seedSenior()` 寫入的 `Config` 設定原本是佔位的「尚未開放」，**現在高中部的選填時間已經跟國中部同步（09/04(五) 17:00～09/06(日) 20:00），記得把 Google Sheets 的 `Config` 分頁 senior 那列的 `SELECT_OPEN`/`SELECT_CLOSE` 也改成一樣的實際時間**（`index.html` 的 `LEVEL_INFO.senior.SELECT_OPEN/SELECT_CLOSE` 已經是新值，只是畫面顯示用；後端真正卡控送出還是看 `Config` 分頁）。高中部的社團簡介已經是固定資料寫在 `index.html` 的 `LEVEL_INFO.senior.clubs`，不用再手動貼 `Clubs` 分頁。
3. `writeStudents_` 會自動用「學號」去重（已存在的學號不會被重複寫入），所以這兩個函式就算不小心重跑，也不會把同一個學生寫成兩列。
4. 高中部的「班級」欄位目前直接沿用學校原始班級碼（例如 `101班`／`201班`／`301班`），沒有座號資料所以座號留空；如果之後想改成中文年級（高一/高二/高三），要同時改 `gas/Seed.gs` 裡的 `students` 陣列或 Sheets 裡的 `Students` 分頁跟前端顯示邏輯。

## 4. 部署成 Web App（第一次）
1. Apps Script 編輯器右上角「部署」→「新增部署作業」。
2. 類型選「網頁應用程式」。
3. 執行身分：**我**。
4. 具有存取權的使用者：**任何人**（學生端不需要登入 Google 帳號就能用）。
5. 按「部署」，複製產生的網址（結尾是 `/exec`）。

## 4-1. 之後改了 `Code.gs`／`Setup.gs`，要怎麼讓網址吃到新版程式碼

⚠️ **不要**再點「新增部署作業」——那個是建立一個**全新的部署、會拿到一個新網址**，你原本 `index.html` 裡貼的那個網址完全不會更新。

正確做法是「更新既有部署」，網址才會維持不變：
1. 「部署」旁邊的下拉箭頭 → **「管理部署作業」**。
2. 找到目前在用的那個「網頁應用程式」部署，點右邊的**鉛筆（編輯）圖示**。
3. 「版本」下拉選單改選 **「新版本」**。
4. 按「部署」。

這樣網址不變，但裡面執行的程式碼會換成編輯器目前的最新版（在編輯器裡直接按執行▶只是測試單一函式，不會影響已部署的 Web App，一定要照上面步驟重新部署才會生效）。

## 5. 接上前端
1. 打開 `index.html`，把最上面的
   ```js
   const WEBAPP_URL = "REPLACE_WITH_YOUR_DEPLOYED_WEB_APP_URL";
   ```
   換成第 4 步拿到的 `/exec` 網址。
2. 用瀏覽器打開 `index.html`（或部署到 GitHub Pages 之類的靜態空間），選「國中部」，確認：
   - 公告文字、社團清單一進頁面就會直接顯示（這些現在是 `index.html` 裡 `LEVEL_INFO` 的固定資料，不用等 API）。
   - 輸入自己的學號 + 正確的身分證後四碼，稍等一下應該會自動帶出班級/座號/姓名（代表 `lookup` 有打通）；只輸入學號、身分證後四碼故意打錯，應該會顯示「身分證後四碼不正確」且不會帶出任何資料。
   - 走完一次選填流程按「送出」，跳出「送出成功」畫面（代表 `submit` 有打通）。
   - 用同一個學號選「查詢我的選填紀錄」，能看到剛剛送出的志願（代表 `query` 有打通）。
   - 用同一學號再送出一次不同的志願，查詢應該把最新那次的結果標成「目前有效」，
     並且能在「查看歷史送出紀錄」展開看到前一次送出的內容（保留完整歷史，不是覆蓋更新）。
   - 故意輸入一個查無此人的學號，應該會跳出手動填寫欄位，且「班級」下拉選單有選項（代表 `classes` 有打通）。

## 5-1. 學號查詢加上「身分證後四碼」，一律必填才能通過驗證

現在 `input-sid`（學號）之外多了一個「身分證後四碼」欄位，**不管填寫志願、補選、還是
查詢我的選填紀錄，身分證後四碼都是必填、且一定要跟 `Students` 分頁對上才會通過**：
- 學號 + 身分證後四碼兩者都對：才會帶出班級/座號/姓名（或查詢模式才會顯示選填紀錄）。
- 學號存在但身分證後四碼是空的、或跟系統對不上：一律顯示「身分證後四碼不正確」，
  不會回傳／顯示這個學號當事人的任何資料。
- 學號本身查無此人：前端才會跳進「查無學號」的手動填寫備援（不需要身分證後四碼，
  因為系統本來就沒有這個人的資料可以核對）。

**填寫志願／補選**另外多一個「沒有身分證字號？改用查無學號方式手動填寫」連結（身分證
後四碼欄位下方）：學生如果真的沒有身分證字號、或忘記了，可以點這個連結直接切到手動
填寫模式（跟查無學號共用同一組班級/座號/姓名欄位，不會自動帶出資料，要自己輸入），
避免卡在必填的身分證後四碼過不去。**查詢我的選填紀錄沒有這個連結**——查詢一定要驗證
身分證後四碼通過才能看到內容，沒有手動繞過的管道，避免任何人只憑學號就查到別人的
選填結果。

只要是沒有身分證後四碼驗證（查無學號、或點了「沒有身分證字號？」）送出的紀錄，
都會在 `Responses` 分頁的 `note` 欄前面自動加註記：
`[查無學號，手動確認身分]` 或 `[沒有身分證字號，手動確認身分]`，方便事後人工核對是不是本人填寫。

如果你的 `Students` 分頁是在這次改版**之前**就已經建立好（例如已經匯入過名冊），
`initSheets()` 不會主動幫舊分頁補欄位，要照以下步驟手動處理：
1. Apps Script 編輯器函式下拉選單選 `addIdLast4ColumnToStudents`，執行——會在 `Students`
   分頁最後補上一欄「身分證後四碼」（已經有這欄的話會直接跳過，可放心重複執行）。
2. 把每一位學生的身分證後四碼實際填進這一欄。**在填齊之前，所有學生的 lookup 都會被
   判定「身分證後四碼不正確」，等於系統暫時無法通過驗證**，請務必填完再開放學生使用。

   ⚠️ **0 開頭的身分證後四碼（例如 0023）**：`addIdLast4ColumnToStudents()` 執行時已經把
   整欄格式設成「純文字」，`updateStudentIdLast4_()` 每次寫入前也會重新確保這件事，
   所以照下面兩種方式填都不會把開頭的 0 弄不見；`Code.gs` 的 lookup 比對也另外做了補零
   防呆（讀到儲存格是數字 23 時會自動當成 "0023" 比對），雙重保險。**唯一要注意的情況**
   是欄位格式事後被別人手動改回「自動」或「數字」，那樣手動輸入 0023 還是會被 Sheets
   吃成 23——如果懷疑發生這種事，重新執行一次 `addIdLast4ColumnToStudents()` 把格式改回
   純文字即可（不會動到已經填好的資料）。
   兩種填法都可以：
   - 手動：直接到 Google Sheets 的 `Students` 分頁一格一格輸入。
   - 批次匯入（本機已經有 `gas/SeedIdLast4.gs`，內含依現成 Excel 名冊萃取出的
     「學號→身分證後四碼」對照表，共 342 筆國中 + 182 筆高中）：
     把該檔整份貼進 Apps Script 編輯器，執行 `updateAllStudentIdLast4()` 即可依學號
     自動補上這一欄；找不到對應學號的會記錄在 Logger（通常是名冊裡不需要選填的
     九年級生，屬正常現象）。
     ⚠️ `gas/SeedIdLast4.gs` 含真實學生身分證後四碼，檔名符合 `.gitignore` 的
     `gas/Seed*.gs` 規則不會被 git 追蹤，**絕對不要**手動把它加進版控或貼到公開的地方。
3. 確認 `Code.gs` 已更新到最新版本並照第 4-1 節步驟重新部署（更新既有部署，不要用「新增部署作業」）。

新建立的分頁（跑 `initSheets()` 從零開始）已經直接包含這一欄，不需要再另外執行
`addIdLast4ColumnToStudents`。

## 5-2. 新增「補選」按鈕（獨立於正式選填的另一組時間窗）

首頁「你想要做什麼？」現在多了一顆「補選」按鈕，跟「填寫志願」是同一套選填流程
（送出時一樣是新增一列、保留歷史，見下面 5-3），差別只在：補選按鈕是否能按，看的是另一組時間窗
`MAKEUP_OPEN` / `MAKEUP_CLOSE`（跟正式選填的 `SELECT_OPEN`/`SELECT_CLOSE`互相獨立），
兩組窗口只要現在落在其中一組裡，後端就會放行送出。

如果你的 `Config` 分頁是在這次改版**之前**就已經建立好，一樣要手動補欄位：
1. Apps Script 編輯器函式下拉選單選 `addMakeupWindowColumnsToConfig`，執行——會在
   `Config` 分頁補上 `MAKEUP_OPEN` / `MAKEUP_CLOSE` 兩欄（已經有的話會跳過）。
2. 呼叫 `writeMakeupWindow_(level, openIso, closeIso)` 幫每個 level 填入實際的補選時間，
   例如在編輯器執行：
   ```js
   writeMakeupWindow_('junior', '2026-09-07T12:30:00', '2026-09-07T13:10:00');
   writeMakeupWindow_('senior', '2026-09-08T00:00:00', '2026-09-08T20:00:00');
   ```
   國中部補選是 9/7(一) 12:30 在電二教室現場集合、用電腦教室的電腦透過「補選」按鈕上網
   填寫，所以時間窗故意設得很窄（12:30～13:10，可依實際課堂/午休時段調整結束時間），
   跟高中部「當天 00:00～20:00 全天線上開放」的形式不一樣。
3. 新建立的分頁（跑 `initSheets()` 從零開始）已經直接包含這兩欄，不需要再另外執行
   `addMakeupWindowColumnsToConfig`。

**「補選」按鈕能不能按，現在是即時讀 `Config` 分頁決定的，不用改 `index.html` 也不用重新
部署靜態頁面**：前端有一支新的 `action=config` API（`Code.gs` 的 `configForLevel_`），頁面
一打開就會呼叫，之後每 30 秒背景重抓一次，抓到 `Config` 分頁的 `SELECT_OPEN`/`SELECT_CLOSE`/
`MAKEUP_OPEN`/`MAKEUP_CLOSE` 就會覆蓋掉畫面上的判斷，所以工作人員之後只要改 `Config` 分頁的
時間，最多 30 秒內、或學生重新整理頁面後就會生效。`index.html` 的 `LEVEL_INFO.<level>.
SELECT_OPEN/SELECT_CLOSE/MAKEUP_OPEN/MAKEUP_CLOSE/MAKEUP_LABEL` 只當作「畫面剛載入、
還沒抓到即時資料前」的備援值與離線後備，兩邊不用手動保持完全一致，但建議還是抓大概一致，
避免使用者在即時資料抓回來前那零點幾秒看到不準確的畫面。

⚠️ `index.html` 最上面的 `DISABLE_TIME_WINDOW = true` 是全域測試開關，為 `true` 時「填寫志願」
會忽略時間窗、一直能按（即使 Config 分頁有設定也一樣忽略）；正式上線前記得改回 `false`，
選填窗口才會真的生效。

**「補選」按鈕刻意不受 `DISABLE_TIME_WINDOW` 影響**，一律照 Config 分頁的
`MAKEUP_OPEN`/`MAKEUP_CLOSE` 實際時間判斷：還沒到開放時間或已經截止，按鈕就會反灰、
不能按；按鈕下方**不會**額外顯示開放/截止時間的文字說明（只反灰，不顯示紅字），
避免測試階段誤以為補選已經開放。現在的 Config（也就是 `index.html` 內建的備援值）是國中 09/07(一)
12:30～13:10（電二教室現場）、高中 09/08(二) 00:00～20:00（全天線上），今天（2026-09-01）
都還沒到，所以補選按鈕現在本來就應該是反灰的——這是正常狀態，不是 bug；要調整就改
`Config` 分頁（或 `writeMakeupWindow_`）的時間，或呼叫 5-2 節的步驟調整。

## 5-3. 送出改成「每次都新增一列」，查詢會列出完整送出歷史

以前同一學號重複送出志願，會直接覆蓋 `Responses` 分頁裡原本那一列（每個學號永遠只有 1 列）。
現在改成**每次送出都新增一列**，同一學號填寫/補選幾次，`Responses` 分頁就會有幾列，
完整保留每一次送出的內容（含當時的備註、送出時間），不會再互相覆蓋。

「查詢我的選填紀錄」也跟著改成會把同一學號的所有列都抓出來，最新一列標成「目前有效的
選填紀錄」直接顯示，比較早的紀錄收在「查看歷史送出紀錄」裡（點開才會展開），不會預設
就把每一次送出都攤開占畫面。判斷哪一列最新是看 `updatedAt`（沒有的話退回 `timestamp`）
排序，不是看列在 Sheet 裡的物理順序，所以就算之後有人手動搬動過 `Responses` 分頁的列，
也不會判斷錯誤。

⚠️ **這是資料模式的改變，`Responses` 分頁會隨著大家重複送出的次數變多而變長**（例如某個
學生改了 5 次志願，就會有 5 列都是他的資料）。如果之後要匯出/統計「每個學生目前的選填
結果」，記得只取每個學號**最新**的那一列（依 `updatedAt` 排序取最後一筆），不要整份直接拿來
當作「一列一個學生」使用，否則同一人會被重複算進去。

## 6. 之後要調整社團、公告、開放時間、名冊
- **社團名額/簡介/費用、公告文字、排除說明、開放/截止時間** → 現在都是固定資料，直接改 `index.html` 裡的 `LEVEL_INFO`，改完重新 push／部署到你放靜態頁面的地方即可（不用動 Apps Script）。記得**開放/截止時間如果改了，Google Sheets 的 `Config` 分頁也要跟著改**，因為 `submit` 送出時是照 `Config` 分頁的時間做真正的卡控，`index.html` 裡的時間只影響畫面顯示跟按鈕能不能按。
- **學生名冊有異動** → 改 Google Sheets 的 `Students` 分頁（這個仍然是動態資料，不用重新部署）。

`Clubs`／`Notices` 這兩個分頁目前後端已經不會讀取了（社團公告改成前端固定資料），留著當備份沒關係，也可以之後想要恢復「後端動態提供」的做法時再用回來。

⚠️ **`Students` 分頁的內容會被伺服器端快取最多 5 分鐘**（`Code.gs` 裡的 `CACHE_TTL_SECONDS`，為了讓學號查詢／班級清單反應更快）。改完名冊想要立刻生效，回 Apps Script 編輯器選 `clearCache` 執行一次即可；不特別處理的話，最晚 5 分鐘後也會自動更新。

## 疑難排解
- **fetch 失敗 / CORS 錯誤**：確認部署設定「具有存取權的使用者」是「任何人」而不是「本機構的使用者」；POST 送出時前端已用 `text/plain` 當 Content-Type 避開瀏覽器的 CORS 預檢請求，不要改成 `application/json`。
- **回應「未知的 action：xxx」**：代表現在這個網址跑的還是舊版 `Code.gs`（沒有這個 action）。多半是用「新增部署作業」建了新網址、卻沒有更新到既有的那個網址——照上面 4-1 的步驟，用「管理部署作業」→ 編輯既有部署 →版本選「新版本」重新部署，網址才會維持不變且吃到新程式碼。
- **doGet/doPost 回傳空白或 500**：到 Apps Script 編輯器「執行項目」（左側時鐘圖示）看錯誤紀錄，或直接在編輯器裡呼叫 `classesForLevel_('junior')` 印出結果排查。
- **身分證後四碼明明填對，還是一直顯示「不正確」**：依序檢查（多半是下面三個原因之一）：
  1. **部署還沒更新**：改完 `Code.gs` 後一定要照 4-1 節「管理部署作業→編輯既有部署→新版本」重新部署，否則網址跑的還是舊程式碼；用瀏覽器打開 `<你的 WEBAPP_URL>?action=lookup&level=junior&sid=某個學號&idLast4=某四碼`，看回傳的 JSON 有沒有 `verified` 這個欄位，沒有的話就是還在跑舊版。
  2. **Students 分頁的「身分證後四碼」欄位其實是空的**：忘記執行 `addIdLast4ColumnToStudents()`／`updateAllStudentIdLast4()`，或執行過但資料沒真的寫進去。直接打開 Google Sheets 的 `Students` 分頁檢查那一欄有沒有值。
  3. **伺服器端快取還沒過期**：`Students` 分頁的資料會被快取最多 5 分鐘（`CACHE_TTL_SECONDS`），剛補完身分證後四碼馬上測試的話，可能還在吃到補之前的舊快取（那時候這欄是空的，永遠比對不到）。回 Apps Script 編輯器執行一次 `clearCache()` 立即清掉快取再重測。
