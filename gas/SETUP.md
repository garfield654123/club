# 部署步驟（GAS Web App + Google Sheets 後端）

## 1. 建立試算表與 Apps Script 專案
1. 到 Google Drive 建立一個新的 Google 試算表，例如命名為「115學年度社團志願選填」。
2. 開啟該試算表 →「擴充功能」→「Apps Script」，會開啟一個綁定此試算表的 Apps Script 專案。
3. 把預設的 `Code.gs` 內容清空，貼上本資料夾的 `Code.gs`。
4. 在專案裡新增檔案 `Setup.gs`，貼上本資料夾的 `Setup.gs`。
5. 再新增一個檔案 `Seed.gs`，貼上本資料夾的 `Seed.gs`（國中部、高中部的完整名冊/社團/公告都整理在這一份檔案裡，不再拆成好幾個 Seed 檔）。

## 2. 建立分頁結構
1. 在 Apps Script 編輯器上方的函式下拉選單選擇 `initSheets`，按執行（▶）。
2. 第一次執行會跳出授權畫面，選你的 Google 帳號 →「進階」→「前往（專案名稱）」→ 允許。
3. 執行完成後回到試算表，應該會看到 `Students / Clubs / Config / Notices / Responses` 五個分頁，且都已經有標題列。

## 3. 匯入國中部／高中部資料（現成資料，一鍵匯入）
1. 函式下拉選單改選 `seedJunior`，執行——會寫入國中部 596 筆學生名冊（七、八、九年級，體育班已排除）、18 筆社團備份、`Config`/`Notices` 各一列 `junior` 的資料。
2. 函式下拉選單改選 `seedSenior`，執行——會寫入高中部 182 筆學生名冊（101/102/103/201/202/203/301/302/303 共 9 班，體育班已排除）與一筆「尚未開放」的 `Config` 設定（因為選填開放/截止時間還沒排定，之後排定後記得同步改 `Config` 分頁跟 `index.html` 的 `LEVEL_INFO.senior.SELECT_OPEN/SELECT_CLOSE`）。高中部的社團簡介已經是固定資料寫在 `index.html` 的 `LEVEL_INFO.senior.clubs`，不用再手動貼 `Clubs` 分頁。
3. `writeStudents_` 會自動用「學號」去重（已存在的學號不會被重複寫入），所以這兩個函式就算不小心重跑，也不會把同一個學生寫成兩列。
4. 高中部的「班級」欄位目前直接沿用學校原始班級碼（例如 `101班`／`201班`／`301班`），沒有座號資料所以座號留空；如果之後想改成中文年級（高一/高二/高三），要同時改 `gas/Seed.gs` 裡的 `students` 陣列或 Sheets 裡的 `Students` 分頁跟前端顯示邏輯。

## 4. 部署成 Web App（第一次）
1. Apps Script 編輯器右上角「部署」→「新增部署作業」。
2. 類型選「網頁應用程式」。
3. 執行身分：**我**。
4. 具有存取權的使用者：**任何人**（學生端不需要登入 Google 帳號就能用）。
5. 按「部署」，複製產生的網址（結尾是 `/exec`）。

## 4-1. 之後改了 `Code.gs`／`Setup.gs`，要怎麼讓網址吃到新版程式碼

⚠️ **不要**再點「新增部署作業」——那個是建立一個**全新的部署、會拿到一個新網址**，你原本 `index.html` 裡貼的那個網址完全不會更新。

正確做法是「更新既有部署」，網址才會維持不變：
1. 「部署」旁邊的下拉箭頭 → **「管理部署作業」**。
2. 找到目前在用的那個「網頁應用程式」部署，點右邊的**鉛筆（編輯）圖示**。
3. 「版本」下拉選單改選 **「新版本」**。
4. 按「部署」。

這樣網址不變，但裡面執行的程式碼會換成編輯器目前的最新版（在編輯器裡直接按執行▶只是測試單一函式，不會影響已部署的 Web App，一定要照上面步驟重新部署才會生效）。

## 5. 接上前端
1. 打開 `index.html`，把最上面的
   ```js
   const WEBAPP_URL = "REPLACE_WITH_YOUR_DEPLOYED_WEB_APP_URL";
   ```
   換成第 4 步拿到的 `/exec` 網址。
2. 用瀏覽器打開 `index.html`（或部署到 GitHub Pages 之類的靜態空間），選「國中部」，確認：
   - 公告文字、社團清單一進頁面就會直接顯示（這些現在是 `index.html` 裡 `LEVEL_INFO` 的固定資料，不用等 API）。
   - 輸入自己的學號 + 正確的身分證後四碼，稍等一下應該會自動帶出班級/座號/姓名（代表 `lookup` 有打通）；只輸入學號、身分證後四碼故意打錯，應該會顯示「身分證後四碼不正確」且不會帶出任何資料。
   - 走完一次選填流程按「送出」，跳出「送出成功」畫面（代表 `submit` 有打通）。
   - 用同一個學號選「查詢我的選填紀錄」，能看到剛剛送出的志願（代表 `query` 有打通）。
   - 用同一學號再送出一次不同的志願，查詢應該看到最新一次的結果（覆蓋更新）。
   - 故意輸入一個查無此人的學號，應該會跳出手動填寫欄位，且「班級」下拉選單有選項（代表 `classes` 有打通）。

## 5-1. 學號查詢改成「學號 + 身分證後四碼」雙重驗證

現在 `input-sid`（學號）之外多了一個「身分證後四碼」欄位，兩個都要輸入且比對正確，
前端才會帶出班級/座號/姓名；只對到學號、身分證後四碼錯誤或空白的話，會顯示
「身分證後四碼不正確」，不會洩漏這個學號當事人的任何資料。

學號存在但忘記身分證後四碼的學生，可以點選「忘記身分證後四碼？改用手動確認」直接改用
手動填寫（跟查無學號一樣不會自動帶出資料，要自己輸入班級/座號/姓名）；這種送出的紀錄
會在 `Responses` 分頁的 `note` 欄前面自動加註記
`[忘記身分證後四碼，手動確認身分]` 或 `[查無學號，手動確認身分]`，方便事後人工核對是不是本人填寫。

如果你的 `Students` 分頁是在這次改版**之前**就已經建立好（例如已經匯入過名冊），
`initSheets()` 不會主動幫舊分頁補欄位，要照以下步驟手動處理：
1. Apps Script 編輯器函式下拉選單選 `addIdLast4ColumnToStudents`，執行——會在 `Students`
   分頁最後補上一欄「身分證後四碼」（已經有這欄的話會直接跳過，可放心重複執行）。
2. 回到 Google Sheets 的 `Students` 分頁，把每一位學生的身分證後四碼實際填進這一欄。
   **在填齊之前，所有學生的 lookup 都會被判定「身分證後四碼不正確」，等於系統暫時
   無法通過驗證**，請務必填完再開放學生使用。
3. 確認 `Code.gs` 已更新到最新版本並照第 4-1 節步驟重新部署（更新既有部署，不要用「新增部署作業」）。

新建立的分頁（跑 `initSheets()` 從零開始）已經直接包含這一欄，不需要再另外執行
`addIdLast4ColumnToStudents`。

## 5-2. 新增「補選」按鈕（獨立於正式選填的另一組時間窗）

首頁「你想要做什麼？」現在多了一顆「補選」按鈕，跟「填寫志願」是同一套選填流程
（送出時一樣以學號覆蓋更新），差別只在：補選按鈕是否能按，看的是另一組時間窗
`MAKEUP_OPEN` / `MAKEUP_CLOSE`（跟正式選填的 `SELECT_OPEN`/`SELECT_CLOSE`互相獨立），
兩組窗口只要現在落在其中一組裡，後端就會放行送出。

如果你的 `Config` 分頁是在這次改版**之前**就已經建立好，一樣要手動補欄位：
1. Apps Script 編輯器函式下拉選單選 `addMakeupWindowColumnsToConfig`，執行——會在
   `Config` 分頁補上 `MAKEUP_OPEN` / `MAKEUP_CLOSE` 兩欄（已經有的話會跳過）。
2. 呼叫 `writeMakeupWindow_(level, openIso, closeIso)` 幫每個 level 填入實際的補選時間，
   例如在編輯器執行：
   ```js
   writeMakeupWindow_('junior', '2026-09-07T00:00:00', '2026-09-07T20:00:00');
   writeMakeupWindow_('senior', '2026-09-08T00:00:00', '2026-09-08T20:00:00');
   ```
3. 同步確認 `index.html` 的 `LEVEL_INFO.<level>.MAKEUP_OPEN/MAKEUP_CLOSE/MAKEUP_LABEL`
   跟 Config 分頁一致——前端這三個值只影響畫面上「補選」按鈕能不能按、顯示的時間文字，
   真正卡控送出的仍然是 Config 分頁裡的值，兩邊沒對齊的話畫面跟實際行為會不一致。
4. 新建立的分頁（跑 `initSheets()` 從零開始）已經直接包含這兩欄，不需要再另外執行
   `addMakeupWindowColumnsToConfig`。

⚠️ `index.html` 最上面的 `DISABLE_TIME_WINDOW = true` 是全域測試開關，為 `true` 時「填寫志願」
跟「補選」兩顆按鈕都會忽略時間窗、一直能按；正式上線前記得改回 `false`，兩組窗口才會真的生效。

## 6. 之後要調整社團、公告、開放時間、名冊
- **社團名額/簡介/費用、公告文字、排除說明、開放/截止時間** → 現在都是固定資料，直接改 `index.html` 裡的 `LEVEL_INFO`，改完重新 push／部署到你放靜態頁面的地方即可（不用動 Apps Script）。記得**開放/截止時間如果改了，Google Sheets 的 `Config` 分頁也要跟著改**，因為 `submit` 送出時是照 `Config` 分頁的時間做真正的卡控，`index.html` 裡的時間只影響畫面顯示跟按鈕能不能按。
- **學生名冊有異動** → 改 Google Sheets 的 `Students` 分頁（這個仍然是動態資料，不用重新部署）。

`Clubs`／`Notices` 這兩個分頁目前後端已經不會讀取了（社團公告改成前端固定資料），留著當備份沒關係，也可以之後想要恢復「後端動態提供」的做法時再用回來。

⚠️ **`Students` 分頁的內容會被伺服器端快取最多 5 分鐘**（`Code.gs` 裡的 `CACHE_TTL_SECONDS`，為了讓學號查詢／班級清單反應更快）。改完名冊想要立刻生效，回 Apps Script 編輯器選 `clearCache` 執行一次即可；不特別處理的話，最晚 5 分鐘後也會自動更新。

## 疑難排解
- **fetch 失敗 / CORS 錯誤**：確認部署設定「具有存取權的使用者」是「任何人」而不是「本機構的使用者」；POST 送出時前端已用 `text/plain` 當 Content-Type 避開瀏覽器的 CORS 預檢請求，不要改成 `application/json`。
- **回應「未知的 action：xxx」**：代表現在這個網址跑的還是舊版 `Code.gs`（沒有這個 action）。多半是用「新增部署作業」建了新網址、卻沒有更新到既有的那個網址——照上面 4-1 的步驟，用「管理部署作業」→ 編輯既有部署 →版本選「新版本」重新部署，網址才會維持不變且吃到新程式碼。
- **doGet/doPost 回傳空白或 500**：到 Apps Script 編輯器「執行項目」（左側時鐘圖示）看錯誤紀錄，或直接在編輯器裡呼叫 `classesForLevel_('junior')` 印出結果排查。
